================================================================================
АЛГОРИТМ ОБНАРУЖЕНИЯ ТОРГОВЫХ СИГНАЛОВ
Математическое описание для специалиста по прикладной математике
================================================================================

Обозначения. Свеча периода t задаётся четвёркой OHLC:
    O_t — цена открытия, H_t — максимум, L_t — минимум, C_t — закрытие,
    V_t — объём (в базовой валюте).
Индекс 0 — текущая (последняя завершённая) свеча, -1 — предыдущая и т.д.


================================================================================
0. ОБЩАЯ СТРУКТУРА КОНВЕЙЕРА
================================================================================

Сигнал рождается как композиция трёх независимых слоёв:

  (A) ДЕТЕКТОР СЕТАПОВ  (SetupEvaluator)
      Жёсткие булевы правила над признаками дневной свечи и макро-контекстом.
      Каждое выполненное правило порождает «срабатывание» (fire) одного из
      типов L1…L5 (лонг) или S1…S6 (шорт). Это бинарный триггер: условие
      либо истинно, либо нет.

  (B) ОЦЕНКА КОНФЛЮЭНЦИИ  (ConfluenceGrader)
      Непрерывная скоринговая модель. Для уже сработавшего сетапа считается,
      насколько независимая мультитаймфреймовая RSI-модель СОГЛАСНА с
      направлением сделки. Возвращает уверенность confidence ∈ [0, 95]
      и число «первичных» подтверждающих структур.

  (C) ВЕТО-СЛОЙ «ДОЖДИСЬ РАЗВОРОТА»  (TrapGate)
      Пост-фильтр. Отклоняет срабатывания контр-трендовых сетапов, если
      разворот, на который они ставят, ещё статистически не начался
      (наклон RSI всё ещё против сделки). По умолчанию выключен.

Формально итоговое множество сигналов:

    Signals = { f ∈ Fires : ¬Veto(f)  ∧  Cluster_ok(f) },

где каждому f приписывается скоринг Score(f) = (confidence, primaries),
а размер позиции вычисляется отдельно по риск-модели (раздел 9).

Файлы: SignalEngine (оркестрация), SetupEvaluator (A),
ConfluenceGrader (B), TrapGate (C).


================================================================================
1. ПЕРВИЧНЫЕ ПРИЗНАКИ ДНЕВНОЙ СВЕЧИ (Features)
================================================================================

Для каждой дневной свечи вычисляются безразмерные признаки. Все «фитильные»
величины нормированы на цену закрытия, что делает их сравнимыми между активами
разной номинальной стоимости.

  Дневная доходность (логарифмически — простая):
      ret_t = C_t / C_{t-1} − 1                                         (1.1)

  Верхний фитиль (отвергнутое движение вверх), доля цены:
      upper_wick_t = ( H_t − max(O_t, C_t) ) / C_t                      (1.2)

  Нижний фитиль (отвергнутое движение вниз):
      lower_wick_t = ( min(O_t, C_t) − L_t ) / C_t                      (1.3)

  Положение закрытия в диапазоне свечи  (closed_high ∈ [0, 1];
  0 — закрытие на минимуме, 1 — на максимуме):
      closed_high_t = ( C_t − L_t ) / ( H_t − L_t ),   если H_t > L_t   (1.4)

  Оборот в долларах:
      turnover_t = V_t · C_t                                            (1.5)

Скользящие статистики по окну W = 20 дней (для всех t ≥ 20):

  Реализованная волатильность (выборочное СКО доходностей):
      m_t   = (1/W) Σ_{j=t-W}^{t-1} ret_j
      vol20_t = sqrt( (1/W) Σ_{j=t-W}^{t-1} (ret_j − m_t)^2 )           (1.6)

  Относительный объём (отношение текущего объёма к среднему за окно):
      vol_ratio_t = V_t / ( (1/W) Σ_{j=t-W}^{t-1} V_j )                 (1.7)

  Средний оборот за 20 дней turnover20_t — порог ликвидности (раздел 9).

Замечание. vol20 (формула 1.6) используется ниже как переменная режима
волатильности volStd, управляющая адаптивными порогами RSI.

Файл: Features, метод computeDaily(), строки 21–74.


================================================================================
2. ИНДИКАТОР RSI (CoinMetrics)
================================================================================

Используется классический RSI(14) по методу Уайлдера (Wilder smoothing).
Пусть Δ_i = C_i − C_{i-1}, и раздельно положительная/отрицательная части:
      g_i = max(Δ_i, 0),     l_i = max(−Δ_i, 0).

Период p = 14. Инициализация средних на первом окне:
      avgG = (1/p) Σ_{i=1}^{p} g_i,     avgL = (1/p) Σ_{i=1}^{p} l_i     (2.1)

Рекуррентное сглаживание Уайлдера (это EMA с α = 1/p) для i > p:
      avgG ← ( avgG·(p−1) + g_i ) / p
      avgL ← ( avgL·(p−1) + l_i ) / p                                   (2.2)

Относительная сила и индекс:
      RS  = avgG / avgL
      RSI = 100 − 100 / (1 + RS)                                        (2.3)

Граничные случаи (исключение деления на ноль):
      avgL = 0, avgG = 0  ⇒  RSI = 50   (нет движения)
      avgL = 0, avgG > 0  ⇒  RSI = 100  (только рост)

RSI считается на трёх таймфреймах: 1h, 4h, 1d. Дополнительно вычисляется
вся серия RSI (calcRSISeries) — она нужна для дивергенций и наклона.

Наклон RSI (дискретная производная, скорость):
      rsiSlope_t = RSI_t − RSI_{t-1}                                    (2.4)

Замечание для контекста MTF (MtfContext) RSI 4h/1h считается по
ПРОСТОМУ среднему (avgG = g̅, avgL = l̅ без сглаживания Уайлдера) — это
сознательное упрощение для внутридневного сканера; формула (2.3) та же.

Файл: CoinMetrics, calcRSI()/calcRSISeries()/rsiFromAvgs(), строки 225–290.


================================================================================
3. РЕЖИМ ВОЛАТИЛЬНОСТИ И АДАПТИВНЫЕ ПОЛОСЫ RSI
================================================================================

Пороги перекупленности/перепроданности RSI не фиксированы, а зависят от
реализованной волатильности volStd (= vol20 из 1.6). Это кусочно-постоянная
функция режима: чем выше волатильность, тем шире полосы (тем экстремальнее
должен быть RSI, чтобы считаться сигналом).

Обозначим полосы: os — oversold (перепродан), ob — overbought (перекуплен),
xLow/xHigh — «экстремальные» уровни.

  volStd ≥ 0.025          ⇒  os=22, ob=78, xLow=15, xHigh=85   (высокая вол.)
  0.012 ≤ volStd < 0.025  ⇒  os=28, ob=72, xLow=20, xHigh=80   (средняя)
  volStd < 0.012          ⇒  os=35, ob=65, xLow=25, xHigh=75   (низкая)
  volStd не задан / ≤ 0    ⇒  os=30, ob=70, xLow=20, xHigh=80   (дефолт)

Файл: ConfluenceGrader, volRegimeBands(), строки 200–212.


================================================================================
4. МУЛЬТИТАЙМФРЕЙМОВЫЙ BIAS RSI (ConfluenceGrader::computeBias)
================================================================================

Это ядро скоринговой модели: непрерывная знаковая оценка bias ∈ [−1, +1],
агрегирующая RSI по трём таймфреймам с весами, и определяющая сторону
(long/short/wait).

4.1. ВЕСА ТАЙМФРЕЙМОВ (старший ТФ важнее):
      w(1h) = 1.0,   w(4h) = 1.6,   w(1d) = 2.4.

4.2. ВКЛАД КАЖДОГО ТАЙМФРЕЙМА.
Для таймфрейма τ с показанием RSI = v:

  Нормированное отклонение от нейтрали 50:
      dist = |50 − v| / 50          ∈ [0, 1]                            (4.1)

  Знак направления (RSI ниже 50 ⇒ перепродан ⇒ ставка в лонг = +1):
      dir = +1, если v < 50;   −1, если v > 50;   0, если v = 50        (4.2)

  Сила сигнала — СТЕПЕННОЙ закон с показателем 1.4 (подчёркивает
  экстремумы, гасит слабые отклонения у 50):
      strength = dist^{1.4}                                             (4.3)

  Штраф за межбиржевой спред (если доступен спред spread_τ > 0):
      strength ← strength · (1 − min(0.4, spread_τ / 30))               (4.4)

4.3. АГРЕГАЦИЯ (взвешенное среднее по присутствующим ТФ):
      bias = ( Σ_τ w_τ · dir_τ · strength_τ ) / ( Σ_τ w_τ )             (4.5)

Нормировка на Σ w_τ означает, что при отсутствии данных части ТФ
относительная важность оставшихся сохраняется.

4.4. ВЫБОР СТОРОНЫ (мёртвая зона ±0.10 вокруг нуля ⇒ «ждать»):
      side = wait,  если |bias| < 0.10
      side = long,  если bias > 0
      side = short, если bias < 0                                       (4.6)

Файл: ConfluenceGrader, computeBias(), строки 382–430.


================================================================================
5. УВЕРЕННОСТЬ (confidence) — АДДИТИВНАЯ МОДЕЛЬ С ПОТОЛКОМ
================================================================================

После выбора стороны строится скалярная уверенность как сумма базового члена
и набора бонусов/штрафов, после чего результат ОБРЕЗАЕТСЯ потолком, который
зависит от числа подтверждённых «первичных» структур.

5.1. БАЗА (сила bias, масштабированная в [0, 80]):
      conf := |bias| · 80                                               (5.1)

5.2. ВКЛАДЫ ПОДДЕРЖКИ ПО RSI.
Пусть на стороне сделки:
  agree   — число ТФ в нужной зоне (long: v ≤ os; short: v ≥ ob),
  conflict— число ТФ в противоположной зоне,
  extremeAligned — число ТФ за экстремальным уровнем (long: v ≤ xLow;
                   short: v ≥ xHigh),
  cascade — длина непрерывной серии ТФ в порядке 1h→4h→1d, где RSI на нужной
            стороне от 50 (каскадное согласие младших со старшими).

      conf += 4 · agree
      conf += 3 · extremeAligned
      conf += 5 · cascade
      conf −= 12 · conflict                                             (5.2)

5.3. ПОДТВЕРЖДЕНИЕ ОБЪЁМОМ (1h vol_ratio):
      vol_ratio ≥ 1.5 ⇒ +6;  ≥ 1.1 ⇒ +3;  ≤ 0.5 ⇒ −5                   (5.3)

5.4. ДИВЕРГЕНЦИЯ RSI↔ЦЕНА (см. 7.1). Если на каком-либо ТФ есть
дивергенция нужного знака (long↔bullish, short↔bearish):
      conf += 12                                                        (5.4)

5.5. НАКЛОН RSI (скорость, формула 2.4). По ТФ {1h,4h,1d} считается
число согласованных (slopeAligned) и явно противоположных (|slope|>0.5,
slopeAgainst) наклонов; slopeOK = (slopeAligned > slopeAgainst):
      slopeOK = true  ⇒ +7
      slopeOK = false ⇒ −10                                             (5.5)

5.6. ПИНБАР (свеча отвержения, см. 7.3). Ищется первый ТФ из {1d,4h,1h}
с пинбаром; совпадающий с направлением даёт бонус, противоположный — штраф:
      bullish/bearish (нужный) :  1d → +10,  4h → +7,  1h → +4
      противоположный          :  1d → −8,   4h → −5,  1h → −3          (5.6)

5.7. ВОЛНОВОЙ КОНТЕКСТ (Elliott-подобная классификация, см. 7.4).
По направлению волны dir∈{up,down} и фазе phase∈{pullback,impulse}:
      сторона совпадает с dir, phase=pullback  ⇒ +8
      сторона совпадает с dir, phase=impulse   ⇒ +2
      сторона против dir, phase=impulse        ⇒ −6                     (5.7)

5.8. ФАНДИНГ (ставка финансирования бессрочного фьючерса). Пороги
HOT = 5·10⁻⁴, VERY = 1·10⁻³ за 8 ч. Для лонга:
      fr ≤ −VERY ⇒ +5;  fr ≤ −HOT ⇒ +3;  fr ≥ +VERY ⇒ −5;  fr ≥ +HOT ⇒ −2
Для шорта знаки зеркальны.                                             (5.8)
Логика: отрицательный фандинг (шорты платят лонгам) поддерживает лонг.

5.9. ПРЕД-ДВИЖЕНЧЕСКИЕ ПАТТЕРНЫ (pre-pump / pre-dump, см. 7.5).
С показателями pp = score(prePump), pd = score(preDump). Для лонга:
      pp ≥ 50 ⇒ +min(10, ⌊(pp−50)/5⌋)        (подтверждение накопления)
      иначе pd ≥ 60 ⇒ −min(8, ⌊(pd−60)/5⌋)    (предупреждение о распределении)
Для шорта роли pp и pd меняются местами.                              (5.9)

5.10. ТРЕНДОВЫЙ ШТРАФ (gate режима). Определяется режим тренда по RSI:
      strongUp   = (RSI_1d ≥ 65) ∨ (RSI_4h ≥ 70)
      strongDown = (RSI_1d ≤ 35) ∨ (RSI_4h ≤ 30)
      regime = up, если strongUp ∧ ¬strongDown; down — симметрично.
      short против up-режима  ⇒ −35
      long против down-режима ⇒ −35                                    (5.10)

5.11. ПАРАБОЛИЧЕСКИЙ ШТРАФ (защита от входа против вертикального движения).
Пусть change24h — суточное изменение в процентах:
      short ∧ change24h > 12 ∧ slopeOK ≠ true ⇒ −12
      long  ∧ change24h < −12 ∧ slopeOK ≠ true ⇒ −12                    (5.11)

5.12. ПОТОЛОК ПО ЧИСЛУ ПЕРВИЧНЫХ СТРУКТУР.
Оцениваются ПЯТЬ «первичных» структур (раздел 6). Пусть k — число
совпавших (match=true), k ∈ {0,1,2,3,4,5}. Тогда потолок:

      PRIMARY_CAPS = [30, 50, 70, 82, 90, 95]   (индекс = k)            (5.12)

Итоговая уверенность:
      confidence = round( clip( conf, 0, PRIMARY_CAPS[k] ) )
      и дополнительно: если side = wait, то confidence = min(confidence, 25).

Содержательный смысл потолка: без структурного подтверждения (k=0)
уверенность не может превысить 30, даже если арифметика бонусов дала больше;
полная уверенность (95) достижима только при всех пяти подтверждениях.

Файл: ConfluenceGrader, computeBias(), строки 433–628.


================================================================================
6. ПЯТЬ «ПЕРВИЧНЫХ» СТРУКТУР (ворота потолка уверенности)
================================================================================

Каждая возвращает пару (match ∈ {0,1}, score ∈ [0,100]). В потолок (5.12)
входит только число match=true; score используется во вспомогательной
статистике (средний балл).

(P1) WAVE — волновой контекст.
      тренд up, фаза pullback ⇒ score=95, match=true
      тренд up, фаза impulse  ⇒ score=60, match=true
      тренд против стороны     ⇒ match=false
(Симметрично для шорта по тренду down.)

(P2) PINBAR — свеча отвержения нужного направления. Детектируется на
ТФ {1d:100, 4h:85, 1h:55 — базовые баллы} по геометрии тела/фитилей (7.3).

(P3) RSI-ВЫРАВНИВАНИЕ. Пусть на n_tf доступных ТФ:
      n_ext  — число RSI за экстремальной полосой (xLow/xHigh),
      n_soft — число RSI в мягкой полосе (os/ob).
      score = min(100, round( (2·n_ext + n_soft) / (2·n_tf) · 100 ))    (6.1)
      match = true при достаточном выравнивании.

(P4) S/R-КОНФЛЮЭНЦИЯ (поддержка/сопротивление). Близость цены к уровню,
измеренная в единицах ATR (7.2): d_atr = |level − price| / ATR.
      d_atr ≤ 0.5 ⇒ score=100;  ≤ 1.5 ⇒ 82;  ≤ 3.0 ⇒ 55;
      зона из ≥3 уровней ⇒ +8.
      Одиночный сильный уровень (strength ≥ 70): d_atr ≤ 0.5 ⇒ 75; ≤1.5 ⇒ 55.

(P5) TRENDLINE — касание трендовой линии. По двум опорным экстремумам
строится прямая y = a·x + b (МНК по пивотам); расстояние цены до линии
в ATR:
      d_atr ≤ 0.5 ⇒ score=100 («касание»);  ≤ 1.5 ⇒ 80;  ≤ 3.0 ⇒ 55;
      иначе ⇒ 30.

Файл: ConfluenceGrader, evalPrimaryWave/Pinbar/Rsi/SRConfluence/Trendline,
строки 218–376; диспетчеризация — строки 604–625.


================================================================================
7. ВСПОМОГАТЕЛЬНЫЕ ДЕТЕКТОРЫ (CoinMetrics)
================================================================================

7.1. ДИВЕРГЕНЦИЯ RSI↔ЦЕНА (detectDivergence, окно lookback=30, рамка
обнаружения локального экстремума window=3 бара). Локальный минимум в точке i:
      C_i < C_{i±k}  для всех k = 1..window.
Сравниваются два последовательных пивота:
      бычья дивергенция:  price_low2 < price_low1  ∧  rsi_low2 > rsi_low1  ∧  RSI < 50
      медвежья:           price_high2 > price_high1 ∧ rsi_high2 < rsi_high1 ∧ RSI > 50
То есть цена обновляет экстремум, а RSI — нет (ослабление импульса).

7.2. ATR(14) — средний истинный диапазон, сглаживание Уайлдера.
      TR_i = max( H_i − L_i,  |H_i − C_{i-1}|,  |L_i − C_{i-1}| )
      ATR_i = ( ATR_{i-1}·13 + TR_i ) / 14                              (7.1)

7.3. ПИНБАР (на завершённой свече, индекс −2). Диапазон R = H − L,
тело body = |C − O|. Бычий пинбар:
      body/R ≤ 0.35   (малое тело)
      lower_wick ≥ 2.0 · body   (длинный нижний фитиль)
      upper_wick/R ≤ 0.20   (короткий верхний фитиль)
      L ≤ (10-бар. минимум)·1.001   (прокол ликвидности)
Медвежий пинбар — зеркально (длинный верхний фитиль).

7.4. ВОЛНА (wave). По пивотам, отфильтрованным порогом размаха 1.5%,
классифицируются последние 6 экстремумов: считаются «higher highs» и
«higher lows». Оба растут ⇒ direction=up; оба падают ⇒ down. Фаза:
если расстояние до последнего экстремума ≤ ATR — impulse, иначе при
откате ≥ 30% импульсной ноги — pullback.

7.5. ПРЕД-ДВИЖЕНЧЕСКИЕ ПАТТЕРНЫ (агрегированные score ∈ [0,100]):
  Squeeze (сжатие волатильности): отношение текущего vol_std к медиане
     за 50 баров r < 1 ⇒ score = (1 − r)·200.
  Accumulation: положительный наклон OBV при почти нулевом наклоне цены.
  Higher-lows: доля восходящих минимумов · 100.
  Parabolic: суточное движение > 1.5 медианных дневных диапазонов.
  Distribution / Climax: дивергенция + близость к экстремуму + всплеск объёма.

Файл: CoinMetrics, detectDivergence (296–349), ATR (351–368),
pinbar (1064–1107), wave (1109–1242), pre-move (733–863).


================================================================================
8. ДЕТЕКТОР СЕТАПОВ — ЖЁСТКИЕ ПРАВИЛА (SetupEvaluator)
================================================================================

Каждое правило — конъюнкция (логическое И) условий над признаками (раздел 1)
и макро-контекстом: fund — фандинг, fund7d — 7-дн. фандинг, oiz — z-score
открытого интереса, fng — индекс Fear&Greed ∈ [0,100], btc_d — доминация BTC.
При истинности правила формируется fire с типом входа, ценой входа entry_px и
стоп-лоссом stop_px. ENTRY_WINDOW — окно жизни ордера (24h/48h).

----- ЛОНГИ -----

L1. Шорт-сквиз лонг [CORE]:
      vol_ratio ≥ 1.0  ∧  fund ≤ −0.0002  ∧  26 ≤ fng ≤ 45
      Вход: стоп-лимит C₀·1.003 (24 ч).
      Стоп: max( L₀·0.995, C₀·0.93 ).
   Идея: отрицательный фандинг + страх = переполненные шорты, готовые к сквизу.

L2. Капитуляционный разворот [МАЛАЯ ВЫБОРКА]:
      vol_ratio ≥ 2.0  ∧  lower_wick ≥ 0.20  ∧  ret ≤ 0  ∧  fng ≤ 25
      Вход: по открытию следующего дня.   Стоп: L₀·0.99.
   Идея: панический слив с длинным нижним фитилём и закрытием в минусе.

L3. Продолжение импульса [CORE]:
      vol_ratio ≥ 2.0  ∧  closed_high ≥ 0.85  ∧  0.04 ≤ ret ≤ 0.15
      ∧  upper_wick ≤ 0.05  ∧  45 ≤ btc_d < 65
      Вход: стоп-покупка H₀·1.002.   Стоп: (H₀+L₀)/2·0.995.
   Идея: сильный импульсный день с закрытием у максимума, без отвержения.

L4. Кластерное дно [УСЛОВНЫЙ]: экстремальный страх после кластерного слива
   (детали — в конфигурации кластер-фильтра, раздел 9).

L5. Откупка отката, мультитаймфрейм [MTF]:
      d_down (дневной даунтренд)  ∧  ( RSI_4h < 40 ∨ RSI_1h < 40 )
      Вход: по рынку.   Стоп: max( d_low3·0.97, C₀·0.90 ).
   d_down вычисляется в MtfContext (раздел 8.1). Лучший по объёму выборки
   лонг (edge ~2.3–2.4). НЕ требует недельного аптренда — это контекст.

----- ШОРТЫ -----

S1. Взрыв переполненного лонга [DORMANT]:
      fund ≥ 0.0005  ∧  fund7d ≥ 0.0003  ∧  26 ≤ fng ≤ 45  ∧  oiz ≥ 1.0
      Вход: sell-limit C₀·1.010 (48 ч).   Стоп: max(H₀, C₀·1.05)·1.005.

S2. Шорт эйфории-ловушки [DORMANT]:
      fund ≥ 0.0005  ∧  fund7d ≥ 0.0003  ∧  fng ≥ 76  ∧  oiz ≥ 1.0
      ∧  btc_d_30d_delta ≥ 0.5
      Вход: sell-limit C₀·1.010 (48 ч).   Стоп: max(H₀, C₀·1.05)·1.005.

S3. Шорт на истощении объёма [CORE]:
      vol_ratio ≥ 10.0  ∧  ret ≥ 0.10
      Вход: если upper_wick ≥ 0.20 — по рынку, иначе sell-limit C₀·1.005.
      Стоп: H₀·1.005.
   Идея: аномальный всплеск объёма (≥10×) на пампе = кульминация.
   ВАЖНО: S3 намеренно ИСКЛЮЧЁН из вето-слоя (см. раздел 10).

S4. Шорт отвержения [CORE]:
      vol_ratio ≥ 2.0  ∧  ret ≥ 0.10  ∧  upper_wick ≥ 0.20  ∧  closed_high ≤ 0.50
      Вход: sell-limit (H₀+L₀)/2 (середина диапазона).   Стоп: H₀·1.005.
   Идея: памп с длинным верхним фитилём и закрытием в нижней половине.

S6. Шорт blow-off на 4h, мультитаймфрейм [MTF]:
      d_up (дневной аптренд)  ∧  4h-свеча: ret ≥ 0.04 ∧ upper_wick ≥ 0.15
      Вход: по рынку.   Стоп: max( H_4h_last, C₀ )·1.005.
   Гейт d_up удерживает S6 от шорта отскоков капитуляции (отскок после
   обвала даёт d_down, а не d_up).

Файл: SetupEvaluator, evaluate() строки 35–178, evaluateMtf()/tryL5/tryS6
строки 190–257.

8.1. МУЛЬТИТАЙМФРЕЙМОВЫЙ КОНТЕКСТ (MtfContext), используется в L5/S6:

  Недельно (w):  SMA10 = среднее 10 закрытий; c4 = close[−4];
      w_up   = close > SMA10 ∧ close > c4
      w_down = close < SMA10 ∧ close < c4
  Дневно (d):    SMA20 = среднее 20 закрытий; c5 = close[−5];
      d_up   = close > SMA20 ∧ close > c5
      d_down = close < SMA20 ∧ close < c5
      d_low3 = min( low[−2..0] )   (3-дн. минимум)
  4h и 1h:  RSI(14) по простому среднему + наклон (2.4) + параметры последней
      свечи {ret, upper_wick, high}.

9. ОТ СИГНАЛА К ПОЗИЦИИ: РИСК, ФИЛЬТРЫ, ПАРАМЕТРЫ (params)
================================================================================

Сработавший и не отвергнутый сигнал превращается в позицию по риск-модели
с фиксированной долей риска. Если риск на единицу = |entry_px − stop_px|,
то номинал позиции (упрощённо):

      risk_$ = equityUsd · riskPct
      qty    = risk_$ / |entry_px − stop_px|,
ограниченный сверху maxNotionalPct (на сделку) и maxPortfolioNotionalPct
(на портфель). Размер дополнительно корректируется на бету актива.

Ключевые параметры торгового блока (common/config/params, ~23 ключа):

  equityUsd = 10000              размер счёта
  riskPct = 0.005                0.5% риска на сделку
  aggressiveRiskPct = 0.0075     0.75% для агрессивных оверрайдов
  maxNotionalPct = 0.20          ≤20% номинала на сделку
  maxPortfolioNotionalPct = 0.60 ≤60% суммарного открытого номинала
  maxConcurrentSingles = 10      ≤10 одновременных сделок
  slippageBpsRoundTrip = 15      0.15% ожид. проскальзывание (туда-обратно)
  timeExitDays = 20              принудительный выход T+20
  trailActivateProfitPct = 0.02  трейлинг включается с +2%
  applyL1ClusterFilter = false   L1 не ставится на паузу
  applyClusterFilterOtherSetups = true  L2/L3/L4 + шорты паузятся после слива
  clusterPauseThreshold = 50     порог числа сливов символа
  fundingMode = 'mean'           дневное среднее фандинга, не точка 16:00 UTC
  requireTurnConfirmation = false  включение вето-слоя (см. раздел 10)
  turnConfirmSetups = ['L2','L5','S4','S6']  сетапы под вето
  parabolicMovePct = 0.12        порог 12% для параболического вето
  turnSlopeEps = 0.0             мёртвая зона наклона RSI (0 = строго)
  minDailyCandles = 60           минимум истории
  minTurnover20dUsd = 5_000_000  фильтр ликвидности $5M (turnover20)
  s6MinTurnover20dUsd = 1_000_000  более мягкий $1M для S6
  blacklist = []                 исключённые символы
  memecoinPriceOnly = ['FET']    пропуск фандинга/OI для этих активов
  dormantSetups = []             отключённые сетапы

10. ВЕТО-СЛОЙ «ДОЖДИСЬ РАЗВОРОТА» (TrapGate)
================================================================================

Жёсткие правила (раздел 8) срабатывают на самой экстремальной свече БЕЗ
подтверждения разворота. Контр-трендовые сетапы (L2, L5, S4, S6) этим уязвимы
к «ловле падающего ножа». Вето-слой добавляет недостающее подтверждение как
ПОСТ-фильтр: он не меняет множество сетапов, только блокирует вход.

Активен только при requireTurnConfirmation = true и только для сетапов из
turnConfirmSetups (по умолчанию {L2, L5, S4, S6}). Использует наклоны RSI
(2.4) на 4h и 1h из MtfContext: s_h1, s_h4. Параметр ε = turnSlopeEps.

Если оба наклона недоступны — слой «открывается» (никогда не блокирует
из-за нехватки данных).

ПРАВИЛО 1 (разворот не начался). Для каждого доступного наклона определим
«против сделки»:
      против = (s < −ε), если long;   (s > ε), если short.
Вето, если ВСЕ доступные наклоны против:
      long:  все s < −ε   ⇒ «RSI ещё падает — разворот вверх не подтверждён»
      short: все s > +ε   ⇒ «RSI ещё растёт — разворот вниз не подтверждён»

ПРАВИЛО 3 (параболика без разворота). Пусть move — дневная доходность ret,
порог par = parabolicMovePct = 0.12. «Разворот начался» = хотя бы один
наклон повернул в сторону сделки (long: s > ε; short: s < −ε). Если разворот
НЕ начался:
      short ∧ move ≥ +par  ⇒ вето «параболический +X% рост, разворот не начат»
      long  ∧ move ≤ −par  ⇒ вето «капитуляция −X%, разворот не начат»

Правило 2 оригинала («свежий импульс против») здесь намеренно опущено: оно
требует волнового классификатора, которого нет в live-MtfContext, и сильно
пересекается с правилами 1 и 3.

Почему S3 ИСКЛЮЧЁН из вето (важная эмпирика): S3 шортит ещё ускоряющийся
blow-off, поэтому «RSI ещё не развернулся вниз» отсёк бы именно те фейды,
которые потом сильнее всего схлопываются (бэктест: оставленные −0.05R против
отвергнутых +2.58R). Подтверждение разворота полезно для откупок (L2/L5) и
шорта отвержения S4, но вредно для шорта истощения S3.

Файл: TrapGate, veto()/stillAgainst()/turnStarted(), строки 67–140.

11. СВОДНЫЙ КОНВЕЙЕР (SignalEngine)
================================================================================

Дневное сканирование (строки 54–197):
  1. Перебор символов вселенной; фильтр ликвидности (turnover20 ≥
     minTurnover20dUsd) и чёрный список.
  2. Расчёт дневных признаков (раздел 1) и текущей строки.
  3. Сбор макро-контекста: фандинг, OI, FNG, доминация BTC.
  4. Сбор MTF-контекста (раздел 8.1): тренды d/4h/1h, RSI, наклоны.
  5. SetupEvaluator.evaluate() ⇒ список срабатываний (раздел 8).
  6. Для каждого срабатывания:
       a. ConfluenceGrader.scoreFire(dir, row): согласие модели + confidence
          + число первичных структур (разделы 4–6). Если сторона модели не
          совпадает с направлением сетапа — скоринг = 0 (модель против).
       b. TrapGate.veto() (если включён) — раздел 10.
       c. проверка кластер-паузы (clusterPauseThreshold).
       d. размер позиции с поправкой на бету (раздел 9);
          условия агрессивного оверрайда.
       e. формирование записи сигнала.
  7. Сортировка сигналов по приоритету сетапа; возврат списка + диагностики.

Внутридневное сканирование (строки 208–316) — для L5/S6 на закрытии каждой
4h-свечи: MTF-контекст «как-на-момент» закрытия 4h, evaluateMtf(), те же
ворота и сайзинг; правило 3 вето пропускается (4h-движение несопоставимо с
24h-порогом).
